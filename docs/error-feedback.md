# エラー発生時のフィードバック（0.2.4 ビルド51）

2026-11-10実装。0.2.4（ビルド51）として署名・送信し、内部TestFlightグループへ追加しました。ビルド50の審査提出を差し替え、2026-11-11にApp Store公開を確認しました。
初期のローカル検証では0.2.5（51）のラベルを使用しましたが、配布用IPAの正式な番号は0.2.4（51）です。

## 動作

フォルダ取得・起動・ディスク挿入・ステート保存／読込などの失敗時に「閉じる」「フィードバックする」を表示します。後者から既存の報告フォームへ進み、固定の症状名と再現手順の入力欄を用意します。

実行停止時は、CPU／互換性エラーと、表示中のDOS文字列 `Bad command or file name` / `Not enough memory` を識別します。通常のDOS終了、実行中の同じ文字列、非表示の古いテキストからは案内しません。これはiOS側の判定で、共有コアの変更はありません。停止したゲスト画面の文字列判定は限定的な手掛かりであり、任意のゲーム固有エラーやフリーズを検出するものではありません。

同一エラーの連続表示を抑えます。ファイル選択中や別のモーダル表示中は発生時の状態を保持し、閉じた後で案内します。背景動作中や「ボスがきた」で隠している間は表示しません。新しいゲームの起動は古い報告の待ち状態を破棄します。ステート操作の明示的な再試行では再度案内できます。

続行可能なゲームは案内中だけ一時停止し、閉じる・報告画面を閉じる・送信成功後の終了で、案内前に実行中だった場合のみ再開します。終了済みのゲストは再開しません。

## 発生時・撮影時のJSON

既存の本文にJSONコードブロックとして添付します。独立したJSONファイルや新しいサーバーフィールドは追加していません。診断情報と画像はそれぞれ初期状態で添付オフで、JSONは送信前にプレビューできます。画面上の表示画像を使用し、未加工のフィルター元画像を添付しません。

- レポートごとのランダムID、取得時刻、アプリ／OSバージョン、端末種別
- CPUクロック、音源、色数、PEGC、フレームバッファ解像度
- INI存在／読込／Start・Root指定の有無（内容は含めない）
- キャッシュ／直接読込の区分、取得中か、停止中か
- 画面寸法・倍率・全画面状態・キーボード配置・接続コントローラー数
- FPSと測定時間、CPU／音声の処理時間、音声バッファの件数、アンダーラン数
- フィルター設定、処理時間、エラー有無、発熱状態・省電力状態
- ゲストの終了区分、実行フレームと表示済みフレーム

未測定FPSはnullです。フィルター処理が非同期の場合、表示画像と実行フレームがずれることがあるため、両方の番号を記録します。各項目は固定の分類・数値・真偽値から作り、ファイル列挙やハッシュ計算を追加しません。JSONは6,000バイト、本文と合計8,000文字までです。

ゲーム本体、セーブ、入力履歴、ファイル名、ゲーム名、フォルダパス、NASアドレス、INI本文、認証情報、端末固有IDは含めません。OSの生のエラー文章はダイアログに表示するだけで、自動入力される報告本文には固定の症状名を使います。利用者自身が書き込む本文や添付画像は送信前に確認が必要です。

匿名／Xは開発者宛てメール、GitHubは本人の確認後に公開Issueへ進みます。GitHubの場合は診断JSONも公開される旨を画面に明記しています。操作するだけで自動送信は行いません。

## 検証

- `feedback_error_smoke`: 実コアで存在しないEXEと正常終了COMを起動して識別、実行中／非表示テキストの除外、CPU／互換性エラーの分類、JSONの凍結・上限・オプトアウトを検証。
- `tools/test_ios_simulator.sh`: 既存の入力・全画面・回転・デモ・ステート46項目が通過。メニューの期待値は追加された「フィードバックする」を含む7項目に更新。
- RetroDOS Tutorial / iOS27.0: 起動失敗ダイアログ→報告、件名自動入力、画像／JSON初期オフ、JSONプレビューと切替、送信せず閉じる、正常終了で案内なしを目視確認。
- 空スロットの読込失敗で加工済み画像が保持され、「閉じる」および報告画面を閉じる操作から実行中へ復帰を確認。検証中はメール・公開Issueを送信していません。

検証用Debug引数: `--feedback-error-fixture`、`--feedback-normal-exit-fixture`。
前者はJSONの検証用コピーをアプリDocumentsへ出力します。これらは `PC98PLAYER_TESTING` 内のみで、本番では有効になりません。

## 制限と未確認事項

アプリがクラッシュ・OSによって強制終了した瞬間の案内や、次回起動時のクラッシュ復旧報告は未実装です。実機での確認と診断JSONを含む実送信の確認も未実施です。

0.2.4配布版のPrivacyInfo.xcprivacyとポリシー本文には、任意の診断データを追加しました。[Appleのデータ型定義](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacycollecteddatatypes/nsprivacycollecteddatatype)に沿い、PerformanceDataとOtherDiagnosticDataをApp Functionality・認証時関連付けあり・追跡なしとして記載しています。App Store Connectでは5種類のデータ（問い合わせ内容、写真またはビデオ、ユーザーID、パフォーマンスデータ、その他の診断データ）の回答を公開済みです。Pagesの新ポリシー本文も公開し、配布IPA内の本文と一致することを確認しました。
