01-B / TRANSFER YOUR FILES

使っているパソコンを選ぶ。

1作品を1フォルダにまとめて ZIP にします。LZH・7z は先にパソコンで展開してください。練習用 ZIP はそのまま送れます。

FROM MAC

Mac から送る

ケーブルで転送する
  1. 端末にアプリを入れ、一度起動します。
  2. データ通信対応ケーブルで接続し、端末をロック解除して「信頼」を確認します。
  3. Finder のサイドバーで端末を選び、「ファイル」を開きます。
  4. RetroDOS Player の欄に ZIP をドラッグします。
AirDrop で転送する

Mac で ZIP を右クリックし「共有」→「AirDrop」で端末へ送ります。受信後は「ファイルに保存」を選びます。保存先が不明なら「最近使った項目」や「ダウンロード」を確認してください。

FROM WINDOWS

Windows から送る

  1. 端末にアプリを入れ、一度起動します。
  2. Apple の「Appleデバイス」アプリを用意します。
  3. ケーブルで接続し、ロック解除・「信頼」を確認します。
  4. 端末の「ファイル」→ RetroDOS Player →「ファイルを追加」で ZIP を送ります。

音楽や写真を一括同期する操作は不要です。

端末に届いたら、この3ステップ。

01-C / CONNECT YOUR LIBRARY

NAS にまとめたゲームも、
「ファイル」から開けます。

パソコンと共有しているフォルダから、遊ぶ作品を選ぶ。
作品ごとに ZIP を転送する以外の選択肢です。

NAS作品をまとめて保管▶「ファイル」SMB で共有に接続▶RetroDOS Player端末へ取得してプレイ

CHECKLIST

接続前の準備

  • NAS 側で SMB のファイル共有を有効にします。
  • 端末を NAS に到達できるネットワークへ接続します。まずは同じ家庭内 Wi-Fi で試してください。
  • サーバ名または IP アドレス、共有名、NAS のユーザー名・パスワードを確認します。
  • 1作品を1フォルダにまとめ、必要なサブフォルダも残します。ZIP は先に展開します。

NAS の管理画面や設定名はメーカーごとに異なります。接続のためにルーターで SMB ポートをインターネットへ公開する必要はありません。

CONNECT

「ファイル」で接続する

  1. ホーム画面から、青いフォルダの「ファイル」アプリを開きます。
  2. 「ブラウズ」の「…」→「サーバへ接続」を選びます。iPad はサイドバーのメニューも確認してください。
  3. サーバ欄に smb://NASの名前 または smb://192.168.1.10 のように入力します。これは例です。自分の NAS のアドレスに置き換えます。
  4. 「登録ユーザ」を選び、NAS のユーザー名・パスワードで接続します。ゲスト接続は NAS 側で許可している場合だけ使えます。
  5. 共有フォルダを開き、ゲームのフォルダが見えることを確認します。

接続したら、RetroDOS Player へ

アプリの「開く」→「ブラウズ」→接続したサーバ→共有フォルダ→作品のフォルダ→右上の「開く」と進みます。初回は端末へのコピーが終わるまで待ってください。次回は「一覧」から登録した作品を選べます。

アプリ内の選択画面に「編集」しか表示されない場合は、ホーム画面の「ファイル」アプリへ戻って接続してください。接続・認証は OS の「ファイル」が扱います。

取得したあとは端末で実行

キャッシュを利用する設定では、ゲーム本体を端末にコピーします。取得済みキャッシュがあれば NAS に接続せず起動できます。キャッシュが消えた場合は元フォルダへの再接続が必要です。作品をコピーできる空き容量をご用意ください。

セーブは端末に保存

元の NAS データは変更しません。セーブと状態保存はアプリ内の別領域に保持し、NAS へ自動同期しません。NAS 側の更新を反映するには、一覧のⓘでキャッシュを削除し、再取得します。保存済みの変更ファイルが優先されます。

この NAS 手順は OS の SMB 接続とアプリのフォルダ取得方式の案内です。各メーカーの NAS での実接続・操作録画は未検証です。

02 / LIBRARY

作品一覧にまとめる

「開く」で作品のフォルダを選んで起動すると、「一覧」から次回も選べます。ゲーム一覧の左上は「閉じる」、右上は内蔵デモを起動する「デモ」です。

開発版プレビュー

一覧

リストとサムネイル

上部の「リスト／サムネイル」で、作品名が並ぶ表示と、画像を並べた表示を切り替えます。どちらも作品をタップして起動できます。キャッシュがある作品にはドライブのマークが付きます。

ⓘ

作品ごとの設定

作品のⓘを押すと、ソフト名・フォルダ名・キャッシュの有無・CPUクロックを確認できます。ここから下の表の操作を選べます。

長押し

タイトル画像を登録

ゲームのタイトル画面でモニターを長押しし、「タイトル画面として登録」を選びます。次に一覧を開くと、その画像がサムネイルに表示されます。登録後は、同じタイトル画面が出たときに画像を自動で保存し直します。

ⓘから選べる操作

CPUクロックを設定
この作品だけのCPUクロックを選びます。「デフォルトを使用」・16・66・133 MHz、または「任意の周波数」（5〜433 MHz）。次回のゲーム起動から適用します。
タイトル名を編集
一覧に表示する名前を変更します。空欄で保存すると自動の表示名に戻ります。
このゲームのキャッシュを削除
端末にコピーしたゲーム本体を消します。元フォルダと保存データは残ります。
今の画面をタイトル画面として登録
プレイ中の作品のⓘにだけ表示されます。モニターの長押しと同じ働きです。
タイトル画面の自動保存を解除
タイトル画像を登録済みの作品に表示されます。自動の保存し直しを止めます。
一覧から削除
作品を一覧から外します。リスト表示では、行を左へスワイプしても選べます。

03 / PLAY

ゲームに合わせて操作する

モニター、操作ボタン、キーボードの3つで操作します。画面の名称は開発中の最新版に合わせています。App Store 版では表示されない項目がある場合があります。

操作ボタンの働き

オプション
音源・色数・表示・コンテンツフィルターなどの設定を開きます。
開く

その時点の状態（ステート）を、スロット1〜8に保存・読込します。ゲーム内のセーブとは別の機能です。

キーボード

キーで操作

複数のキーを同時に押せます。長押しはリピートします。SHIFT・CTRL・GRPH は、単独でタップすると押したままになり、もう一度タップで解除します。押しながら別のキーを使った場合は、指を離すと解除します。CAPS・かなは切り替え式です。外付けキーボードも使えます。

コントローラー

画面内コントローラー

キーボード／コントローラー／タッチパッドの切り替えは、3本指で左右へスワイプします（右＝次のモード、左＝前のモード）。「キー設定」で、上下左右と A・B にアルファベット・数字・ファンクションキー・Enter などを割り当てます。割り当てはゲームごとに保存します。

マウス

画面を直接操作

モニターをドラッグでカーソル移動、1本指タップで左クリック、2本指タップで右クリックです。操作ボタンの「右クリック」も使えます。モニターをダブルタップすると全画面になり、もう一度ダブルタップすると通常表示に戻ります。

開発版プレビュー

全画面でもコントローラーを使う

左の方向入力、右のA・B、その上の一時停止・再生を使って操作します。横向きの既定表示は「オプション → 表示 → 横画面の全画面でコントローラーを表示」で変更できます。

LIMITS

知っておきたい限界

  • 判定は端末内で行い、画面を外部へ送信しません。
  • 誤検出と見逃しがあります。ドット絵やイラストでは特に起こります。
  • 文章と音声は判定しません。
  • 残酷描写の判定は試験的な機能です。
  • 判定中は直前の画像を保持するため、表示が遅れることがあります。
  • ぼかしとモザイクは、色や形を一部残します。

05 / NEED A HAND?

つまずいたら、ここから。

SuperDepth が起動しない場合は、まず 「Bad command or file name」が出るときをご覧ください。

困ったことを報告したい。どこから送ればよい？

「オプション」→いちばん下の「バージョン」で報告フォームを開きます。件名と症状を書き、匿名・GitHub・Xから選んで送信してください。上の画像付き3ステップでも確認できます。アプリ内フォームは0.2.4（ビルド50）からの機能です。

アプリとOSのバージョンは自動で添えられます。作品名、端末の機種、保存先の種類（このiPhone内・iCloud・NASなど）、操作手順、エラーの文字、毎回か時々かを分かる範囲で書いてください。ゲーム本体・セーブデータ・操作履歴は自動添付しません。

入力中のキーボードが邪魔なときは「キーボードを閉じる」を押せます。報告画面の外を触っても閉じません。中止する場合は左上の戻るボタン、または「閉じる」を使います。

ゲーム画面のスクリーンショットも添付できる？

ゲームのモニター部分を長押し→「フィードバックする」を選びます。報告フォームに画像の候補が表示されるので、内容を確認して「ゲーム画面を添付」をオンにしてください。初期状態はオフです。オプションのバージョンから開いた場合は画像が付きません。

添付するのはゲーム表示領域です。匿名・Xの画像は開発者へのメールに添付されます。GitHubを選んでも、画像は公開Issueへ自動添付されません。 受付側で非公開に保管されます。個人情報やパスワードが写っていないか確認してください。

匿名・X・GitHubの違いは？ 返信はもらえる？

匿名とXは開発者へのメール受付です。公開Issueには自動登録しません。GitHubは公開Issueになり、GitHub上で経過を確認できます。GitHubの投稿前には公開内容の確認画面が出ます。

匿名の場合、メールアドレスは自動取得しません。 そのため個別返信ができない場合があります。Xはユーザー名を添えて受け付けますが、DMや返信を自動送信する機能はありません。いずれも、回答・修正時期をお約束するものではありません。

認証は各サービスの画面で行います。本アプリや受付サーバーにGitHub／Xのパスワードを入力する必要はありません。報告しなくても、アプリの通常機能を利用できます。

送れない・認証で戻ってしまう・受付できたか分からない
  1. 件名と症状を両方記入し、インターネット接続を確認します。
  2. 匿名の確認画面、またはGitHub／Xの認証画面を最後まで進め、アプリに戻ります。認証をキャンセルした場合は送信されません。
  3. 完了画面の受付番号、GitHubの場合はIssueのURLを確認します。受付番号は報告を識別する番号で、進捗を閲覧するページではありません。
  4. エラー時は表示された文言を控えてください。短時間に何度も送信せず、少し時間を置いて確認します。

フォーム自体が使えない場合はGitHubの報告窓口へ。GitHubアカウントが必要で、投稿は公開されます。解決のためにアプリを削除する必要はありません。

報告した情報はどこに保存される？

報告はCloudflareの受付サーバーを経由します。受付データ・画像・認証したユーザー情報は30日で削除します。開発者へ届いたメールと公開Issueは、問い合わせ対応と修正のため別に保持します。削除の相談は受付番号を添えてください。詳しくはプライバシーポリシーをご覧ください。

SuperDepth で「Bad command or file name」が出るとき

0.2.3 を公開しました。 SuperDepth の起動時にアプリ内部の識別子がパスに混ざり、「Bad command or file name」が出る不具合を修正しました。

0.2.2 では、親フォルダから開いたときに加え、DEPTH.EXE が直下にある DEPTH フォルダを直接開いても、このエラーが出る場合があります。INI は任意です。INI がないときは「起動するプログラム」から実行ファイルを選べます。

0.2.3 に更新して、同じ条件で再確認する

  1. App Store の RetroDOS Player で 0.2.3 に更新します。
  2. 前回と同じ ZIP を「ファイル」アプリで展開します。PC98PLAYER.INI は追加せず、DEPTH.EXE と付属データが直接入っている DEPTH フォルダを使います。
  3. RetroDOS Player の「開く」で DEPTH フォルダに入り、右上の「開く」を押します。たとえば ゲーム集/DEPTH/DEPTH.EXE なら、DEPTH を開きます。
  4. 「起動するプログラム」が出たら DEPTH.EXE を選び、SuperDepth のタイトル画面まで進むか確認します。

エラーが続く場合は、アプリのバージョン、端末と iOS のバージョン、保存先（このiPhone内・iCloud Drive など）、候補に表示されたパスとエラーをお知らせください。

NAS が表示されない・接続できない

まずアプリを離れ、「ファイル」アプリ単体で接続できるか確認します。同じ Wi-Fi、NAS の SMB 設定、IP アドレス、共有権限、ユーザー名を見直してください。ゲスト Wi-Fi では機器同士の通信が制限される場合があります。NAS のパスワードを GitHub などに投稿しないでください。

ゲームフォルダはどこに置く？

端末に置く場合は「ファイル」→「このiPhone内／このiPad内」→「RetroDOS Player」が見つけやすい場所です。アプリを一度起動すると表示されます。必要に応じて、その中の Games に1作品ずつまとめてください。「ダウンロード」、iCloud Drive、接続済みのNASに置いたフォルダも、アプリの「開く」から選べます。

ZIPは先に「ファイル」で展開します。アプリの「開く」で作品のフォルダに入り、右上の「開く」を押します。起動ファイルが薄く表示されていても、フォルダを選ぶ操作はできます。展開後に同名のフォルダが重なっている場合は、まず起動ファイルとゲームデータが入っている内側の作品フォルダを選んでください。

ゲームフォルダには何が必要？

作品の説明書に従い、PC-98／DOS用の起動ファイル（.BAT、.COM、.EXE）と、画像・音楽などの付属データ一式を入れます。展開したときのファイル名とサブフォルダ構成を保ってください。Windows版の PC98PLAYER.EXE を一緒に転送した場合は、候補に出ても作品の起動ファイルを選んでください。

SuperDepth/
  DEPTH.EXE
  DEPTH.BGM
  …ほかの付属データ
  PC98PLAYER.INI  （任意）
PC98PLAYER.INI がある場合と、ない場合は？

INIは任意です。選ぶフォルダの直下に PC98PLAYER.INI があり、[PC98PLAYER] に有効な Start が指定されていれば、そのプログラムが自動起動します。たとえば、DEPTH.EXE とINIを同じフォルダに置いた場合は次のように指定します。

[PC98PLAYER]
Start=DEPTH.EXE

Start は選んだフォルダを基準にしたパスです。Root を指定した場合は、選んだフォルダからの相対パスで Root を書き、Start はその Root を基準に書きます。たとえば親フォルダのINIに Root=DEPTH、Start=DEPTH.EXE と書くと、親フォルダ内の DEPTH/DEPTH.EXE を指定できます。

INIがない場合や Start が空の場合は、「起動するプログラム」で作品の説明書にあるBAT・COM・EXEを選びます。INIが子フォルダにだけある場合は、その子フォルダを「開く」で選ぶと自動起動の設定が読み込まれます。親フォルダから選んで「Bad command or file name」が出た場合は、バージョン別の確認手順をご覧ください。

ゲームが動かない・音が出ない

必要なデータが揃っているか、説明書の起動プログラムを選んだか、対応する音源・色数かを確認します。一時停止中なら「▶︎ / Ⅱ」で再開してください。音源・色数の変更を適用すると再起動するため、先にゲーム内で保存します。ソフトごとの互換性対応が必要な場合もあります。

画面が出ない・「保護フィルター」と表示される

コンテンツフィルターが有効なときは、判定が終わるまで画像を表示しません。状態表示が「保護フィルター: 判定中…」のままなら少し待ってください。エラーが表示された場合は、「オプション → コンテンツフィルター」で設定を確認します。フィルターを使わない場合は両方オフにして「適用」を押します。

キャッシュを消すとセーブも消える？

一覧のⓘにある「このゲームのキャッシュを削除」では、セーブは消えません。「一覧から削除」も一覧から外すだけです。ただし、アプリを削除するとアプリ内のセーブ・状態保存も失われます。不調時の最初の対処としてアプリを削除しないでください。元のゲームフォルダをコピーするだけでは、別領域のセーブのバックアップにはなりません。

解決しない場合は、アプリからフィードバックをお寄せください。アカウントなしでも報告できます。ゲーム本体や認証情報は送らないでください。
