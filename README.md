# PC98PLAYER-iOS

[PC98PLAYER-MAC](https://github.com/koshikawa-masato/PC98PLAYER-MAC) の `1ca10ac` をベースにしたiOS向け派生版です。原作は [Imaha486/PC98PLAYER](https://github.com/Imaha486/PC98PLAYER)。C++のエミュレータコアとMITライセンス、変更履歴を引き継いでいます。同じアカウントの既存フォークとは別名で作るため、GitHub上では独立した派生リポジトリとして管理します。

Mac／NASをゲーム本体の保存場所として使い、iPhoneにはプレイ用の一時キャッシュを取得します。セーブとステートは別領域に保持します。ゲーム、ROM、商用フォントは同梱しません。

C++の共通エミュレータコアをUIKitで動かすiOS版です。iOS 17以降を対象とし、iPhone DuoのiOS 27.0.1でも手動の上下表示を使えます。Duoの自動検出を含むビルドにはXcode 27.1以降のSDKが必要です。古いSDKでは手動レイアウトのみをコンパイルします。

## 外観

ロゴを入れず、アイボリーのCRT筐体とPC-98キーボードをUIKitで描画しています。奥まった画面枠・台座・電源ランプ、灰色の修飾キーと明るい文字キー、かな刻印、押下時の沈み込みを備えています。画面自体は640×400の比率を保ちます。写真の素材はアプリに含めません。

通常iPhoneの縦画面では操作性のためテンキーと補助キーを下段に配置しています。Duo表示（iOS 27.0.1では手動指定）、または公開ヒンジAPIでDuoを検出した場合は参考写真の実物配列へ切り替え、右端のテンキー、独立したカーソル群、ファンクション列のVF1〜VF5、左下のランプを再現します。Enterの段差と当たり判定、Shiftとスペースの幅も実物の比率に合わせています。Duoでは下側領域の幅を優先して広げ、上下の筐体余白を減らします。縦長の外側画面や左右分割でもキーが縦に伸びすぎないよう、キーボード全体の高さは幅の44%までに制限します。キーの並び・横方向の比率・段差のあるEnter・テンキーの位置を保持し、刻印は文字自体を引き伸ばさず拡大します。細いキー間は近い方のキーへ割り当てます（Enterの欠けた部分と広い筐体余白は除外）。モニター下の物理ボタン風の操作部から、従来どおりゲーム選択・保存・読込・表示切り替えができます。

## データの置き方

アプリ本体にゲームを入れる必要はありません。ゲームのフォルダをそのまま選びます。

- 端末内：Filesの「このiPhone内 → PC98PLAYER → Games」にフォルダを置き、「開く」で選択。
- NAS：Filesの「… → サーバへ接続」でSMB共有へ接続してから、「開く」でそのゲームフォルダを選択。
- 選択した場所はbookmarkで記録し、「場所」から再び選べます。パスワードはアプリに保存しません。接続・認証はFilesが扱います。アプリ内SMBクライアントやNAS自動検出は未実装です。

ゲーム本体はファイルコーディネータを通じて `Library/Caches/PC98Games` に一時取得します。取得が完了したコピーだけを使います。キャッシュがあればNASに接続せず起動でき、キャッシュが消えた場合は元の場所から再取得します。元データを移動・上書きしません。大量のゲームをまとめず、プレイするゲーム単位のフォルダを選んでください。現在は選択フォルダを丸ごと取得するため、その分の空き容量が必要です。

ゲームが書き換えたファイルとステートは `Library/Application Support/PC98Saves/<ゲームID>/files` に保存します。読み書きで開いただけでは永続コピーを作らず、実際の書き込みでファイル単位のコピーを作ります。削除の記録も保存するため、再取得した元ファイルが勝手に復活することはありません。**「場所 → ゲーム本体のキャッシュを消去」で保存データは消えません。** 保存データをNASへ自動同期する機能はありません。アプリを削除すると端末内の保存データも削除されます。

NAS上のゲームを更新したときはキャッシュを消去してから再取得します。変更済みファイルは保存領域のものが優先されます。Root=を使う場合は、選択フォルダ内を指す相対パスにしてください。ディスク・CDなどのホストパスにも選択フォルダ内の相対パスを使います。

Duoのモニターは枠を薄くし台座を省いて、上側領域の高さを優先して拡大します。上下分割でキーボード上に十分な余白がある場合は操作ボタンをそこへ移し、上側を画面に使います。ゲームの640×400（8:5）の比率は保ち、周囲の余白はベージュに統一しています。

## iPhoneとDuoの操作

実機確認用などに配置した取得済みキャッシュは、「場所」のゲーム名（キャッシュ）から開けます。本体データは引き続きキャッシュ領域だけに置き、セーブ／ステートは別の永続領域に保存します。キャッシュを消去した場合は、Mac／NAS上の元フォルダから再取得してください。

ソフトキーボードはキーを押すたびに軽い触覚フィードバックを返します。修飾キー・VFキー・テンキーも対象で、長押しリピートやキーを離す操作では振動を繰り返しません。対応する実機で動作し、シミュレータでは振動の感触を確認できません。

Duoでは背面カメラのある半分をキーボード側にして置けるよう、上下反転を含む全方向を許可します。通常iPhoneは縦向きを維持します。時計などのシステム表示の位置はOSが決めるため、アプリから下半分への移動は行いません。Duoのゲーム表示中はステータスバーを隠して画面を広く使います。内側カメラを含むOSの有効な遮蔽予約領域を避け、残る領域で8:5のモニターを最大化します。

内画面の仕様は [Appleの技術仕様](https://www.apple.com/iphone-duo/specs/) で7.6インチ・1878×2670ピクセルです。シミュレータ／[App Store向け画像](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications) は2007×2853ピクセル（横向き2853×2007）で、今回のUIKitの論理領域は669×951ptでした。実パネルの解像度と描画用画像のサイズは区別します。配置には固定の解像度を使わず、その時点のview.bounds、safe area、折り目の予約領域を使います。予約領域のframeにはOS側の操作余白も含まれます。

Debug版を `--demo --layout-report` で起動すると、表示中の画面・ビュー・safe area・折り目・上下パネルの寸法をDocumentsの `layout-report.json` へ出力します。閉じた外画面と開いた内画面を切り替えて実測するための開発用機能です。

通常のiPhoneは、縦画面では上にモニタ、下にPC-98キーボード、横画面では左にモニタ、右にキーボードを表示します。モニタの8:5の縦横比を保ち、横画面はキーボード側を少し広めに配置します。Duo表示を指定した場合とヒンジを検出した場合は、折り目に合わせて回転できます。

「オプション → 表示 → Duo上下表示を固定」で、上側に640×400のモニタ、下側にPC-98ソフトキーボードを表示します。iOS 27.0.1ではこの手動指定を使います。画面の開閉による物理ディスプレイの選択はOSが管理します。

iOS 27.1以降は公開の `UIHingeInteraction` で半開きを検出し、Duo表示に自動追従します。OSが返すdivision予約領域を避けて配置します。横方向の折り目なら上下、縦方向の折り目なら左右に分けるため、ノートPC型に使うときは横方向の折り目になる向きで使ってください。予約領域を取得できないときと手動指定時は画面中央を分割位置とします。外側画面を含め、画面の移行そのものをアプリから強制しません。

- 通常キーは押している間だけON。複数キーを同時に押せます。長押しはリピートします。
- 複数の指で同時押しできます。Shift＋文字、矢印＋スペースなどを個別に保持し、指を離したキーだけ解除します。押したまま隣のキーへ滑らせる入力にも追従します。
- SHIFT / CTRL / GRPHは、押しながら別キーを使うと、指を離したときに解除します。単独タップでは従来どおり保持し、再タップで解除します。CAPS / かなは切り替え式です。
- F1〜F10、VF1〜VF5、STOP、COPY、XFER/NFER、HELP、ROLL、INS/DEL、矢印、テンキーを搭載。VF1〜VF5はスキャンコード52h〜56hを送信し、BIOS入力とSHIFT／CTRL併用にも対応します。
VFキーのコードは [TMKの実機キーボード資料](https://github.com/tmk/tmk_keyboard/wiki/PC-9801-Keyboard)、修飾時のBIOSコードは [DOSBox-Xの対照表](https://dosbox-x.com/doxygen/html/bios__keyboard_8cpp_source.html) を参照しています。

- 外付けキーボードもUSB HIDからPC-98スキャンコードへ変換します。OSが予約するキーは受け取れない場合があります。
- モニタをドラッグしてマウス移動、一本指タップで左クリック、二本指タップで右クリック。上部の「右クリック」も使えます。
- 「保存」「読込」は8スロット。アプリが非アクティブになったら一時停止し、キーを解放します。復帰後は▶︎で再開します。
- 「場所 → オリジナルDOSデモ」でゲームデータなしに画面と入力を試せます。

## ビルド

```sh
./build_ios.sh
# Xcodeで開く（生成後）
open build/ios-iphonesimulator/PC98PLAYER.xcodeproj
# 実機用の未署名ビルド
IOS_SDK=iphoneos ./build_ios.sh
```

シミュレータ向け出力は `build/ios-iphonesimulator/Debug-iphonesimulator/PC98PLAYERiOS.app` です。実機実行にはAppleのDevelopment Teamと署名設定が必要です。自分のTeam IDを指定すると、自動署名を有効にした実機ビルドを作れます（Xcodeのアカウント設定と証明書が必要です）。

```sh
IOS_SDK=iphoneos IOS_DEVELOPMENT_TEAM=YOUR_TEAM_ID ./build_ios.sh
# Release構成も指定可能
IOS_SDK=iphoneos IOS_CONFIGURATION=Release ./build_ios.sh
```

USBでiPhoneを接続し、ロック解除・信頼許可・デベロッパモードを確認してから、インストールと起動を実行できます。

```sh
xcrun devicectl list devices
IOS_DEVELOPMENT_TEAM=YOUR_TEAM_ID ./tools/install_ios_device.sh DEVICE_UDID
```

`IOS_BUNDLE_ID` で自分用のBundle IDに変更できます。生成された実機用プロジェクトをXcodeで開き、接続したiPhoneを選んで実行します。署名なしの `.app` はそのまま実機にインストールできません。TestFlightで内部配信中です。App Store版0.2.0 (5)は2026年10月26日に審査へ提出し、審査待ちです。

## 検証

Mac側のCTestでCPU・音声・ステートに加え、コピーを作るタイミング、元ファイルの不変性、削除と再作成、ディレクトリ名変更、キャッシュ再取得後の保存データを検証します。

Debugビルドは `--smoke-test` を付けて起動すると、キーのアクセシビリティ操作経路からゲストへ入力し、小文字／SHIFT付き大文字、修飾キー、ステート復元、手動の上下配置を確認します。結果はDocumentsの `smoke-result.json`、画面は `duo-smoke.png` に出力します。商用ゲーム・NAS実接続・Duo実機のヒンジ遷移は別途確認が必要です。自動テストは物理的なタッチやヒンジ遷移そのものの検証ではありません。

既存Windows版のMIDI出力、ゲームパッド、F11設定画面、メモリ／コードエディタ、インストールアシスタントはiOS版でも未対応です。

```sh
# シミュレータを起動してから実行（DEVICE_UDIDはsimctl list devicesで確認）
./tools/test_ios_simulator.sh DEVICE_UDID
```

実行結果と画面を `out/ios-smoke/` にコピーします。テストはオリジナルデモの専用保存スロットを使用し、利用者のゲームフォルダは操作しません。

## 派生元と開発

`origin` は本リポジトリ、`mac-source` はMac派生元、`upstream` は原作です。MacとWindowsのソースも共通コアの互換性維持のため残しています。従来の説明は [Mac／Windows版README](README-MAC-WINDOWS.md) を参照してください。iOS用のCIではコアのテスト、シミュレータの入力・ステート・上下表示のテスト、実機向け未署名ビルドを実行します。CIのZIPは開発用で、TestFlight配布物ではありません。

### iPhoneからNASを開く場合

「ファイル」でNASへ接続し、PC98PLAYERの「開く」からゲームのPC98PLAYER.INIがあるフォルダーを選択します。一度取得したゲームは「場所」から開けます。

一部のQNAPなどでは、iOSのフォルダー列挙が空を返すことがあります。その場合はMacで `python3 tools/index_game_folder.py /Volumes/Public/PC98PLAYER/AliceSoft/Games/RanceIV` を実行してから開いてください。ライブラリー全体には `--recursive` を指定できます。ゲームを更新した場合は一覧を作り直してください。アプリは一覧のサイズ・SHA256を照合して端末キャッシュを作成し、セーブを別領域に保持します。今回のNASのGames内26フォルダーには一覧を作成済みです。

[Apple Developer Forumsの同症状報告](https://developer.apple.com/forums/thread/831359)

モニタの表示領域をダブルタップすると、ゲーム画面だけを全画面表示します。縦横比を保ったまま画面内に最大表示し、ドラッグでマウス移動、一本指タップで左クリック、二本指タップで右クリックができます。もう一度ダブルタップすると元のモニタ・キーボード配置へ戻ります。全画面中はキーボードとツールバーを非表示にします。全画面のモニタを約0.5秒長押しすると「一時停止」「リセット」の簡易メニューを開けます。このメニューで一時停止した後は、一本指タップ（左クリック）で再開します。再開用のタップはゲームには送られず、次のタップから左クリックになります。リセットは確認後に実行します。通常表示では長押しメニューは出ません。

### 音源・16色／256色

縦画面のCAPS／かな／GRPHランプの右にある「オプション」で、OPN／OPNAと16色／256色を選べます。音源・色数を変更して「適用」するとゲームを再起動します。表示設定のみの変更では再起動しません。ツールバーの「リセット」は確認後に現在のゲームを起動し直します（保存済みデータは保持）。設定は次回も保持します。外部BIOSは不要です。現在の256色対応は640×400のRance IVを主な確認対象としています。[対応範囲と検証](docs/256-color.md)を参照してください。

一時停止時には停止前の音声バッファを破棄し、再開後の新しいPCMを16msでフェードインします。画面切り替え中の音切れを防ぐため、音声消費に合わせて約80msの予備を補充します。実機録音による比較と再現方法は[音声の検証記録](docs/audio-playback.md)を参照してください。

TestFlight配布ビルドの作成手順は[docs/testflight.md](docs/testflight.md)を参照してください。

### シミュレータでMacにマウントしたNASを直接読む

MacでNASをマウントしてから、次のコマンドでシミュレータへ最新版を導入します。

```sh
tools/install_ios_simulator_nas.sh DEVICE_UDID /Volumes/Public/PC98PLAYER/AliceSoft/Games
```

「場所」に各ゲームが「NAS直接」として表示されます。ゲームの元ファイルはNASから読み、書き込みは従来の保存用オーバーレイへ分離します。元フォルダーをローカルへ複製する必要はありません。NASのパスはシミュレータ内に記録するため、次回の通常起動でも「場所」から選べます。NASが未接続なら、Macで同じ共有をマウントし直してください。

このホストパス連携は`TARGET_OS_SIMULATOR`限定です。実機／App Store版では、ファイルアプリで選んだゲームを一時キャッシュへ取得する従来の方式を使います。

### Duoの「ボスがきた」モード

「オプション」→「表示」の「ボスがきた」をオンにして「適用」すると、Duoを閉じた際にゲームと音声を一時停止し、アウターのアプリ画面を黒く覆います。開き直しても自動再生せず、▶︎で再開します（全画面中はダブルタップで通常表示へ戻せます）。設定は次回起動にも引き継ぎます。画面の電源や時計などのOS表示を消す機能ではありません。ヒンジ通知を利用できるDuoが対象です。

Duoのインナースクリーンを左右開き／横長の全開状態にすると、モニタを縦横比8:5のまま自動で全画面表示します。上下開きへ戻すとキーボード・操作ボタンを復元します。左右開きでもダブルタップで通常表示へ戻せ、同じ姿勢の間はその選択を維持します。通常のiPhoneの横画面や「ボスがきた」モードは従来どおりです。
